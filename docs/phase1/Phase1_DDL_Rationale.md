# Phase 1 DDL rationale

**Draft against main `5f46f9b03f24f4776ffb09feb390906b0ca75fdb`; Albania only.** The [accepted Atlas plan](https://github.com/FTFNAnalytics/digitaldemocracy/blob/5f46f9b03f24f4776ffb09feb390906b0ca75fdb/docs/atlas-plan.md) and Phase 0 handoff govern this design. No offices, regional rows or application code are included.

**Two files, two databases.** `001_atlas_master.sql` defines the master; `001_atlas_attempt_log.sql` defines the separately committed sibling audit ledger. `dataset_release` is immutable metadata for one source-dataset lineage. Its unique fingerprint covers effective package inputs (including classification files), applicable overrides and adapter/method/schema versions; attempt IDs and unrelated lineages are excluded. `publication_release` selects one release per lineage. Re-importing unchanged inputs creates a new `ingest_attempt` pointing to the same release. `publication_receipt` identifies the physical swap for crash reconciliation without becoming a research citation. The ledger deliberately uses a checked logical release reference across files.

**Small active projection, auditable releases.** Core tables store the currently published records. Previous row versions remain recoverable through the plan’s immutable inputs and full release backups, rather than a second version of every live table. An incomplete refresh carries omitted records and their original provenance forward; effective input checksums include the retained source inputs. No silent deletion or same-release content mutation is allowed. Release rows only become public after staging validation and atomic publication. Country entries can exist with no offices; many lineages, countries and territories can coexist, allowing later LatAm/NZ continuity without redesigning the core keys.

**Identity and evidence.** Offices use `(id_namespace, office_id)`; events use `(id_namespace, office_id, history_key)` and preserve public event IDs. Proceedings and result rows carry that entire event key. Geography parents may be null. Party mappings retain country/source/election context. Typed `record_locator` foreign keys support reusable evidence links and crosswalks without unchecked polymorphic targets. `unresolved_evidence` preserves unmatched tokens separately from resolved source references. No absent source publisher or URL is fabricated.

**Research semantics.** `office_tier_classification` must exist for every office and links to the checksummed classification input. It stores geographic tier separately from `office_type`; `national` maps to `national_context`, while `unknown` becomes null with explicit review status. `other` and territories are supported. Albania’s 122 municipal offices and zero regional offices are valid. `research_date` preserves precision and certainty; results retain value/status pairs so unknown differs from zero. Unprojected source sheets and artifact locators remain in `retained_input`.

**Boundary of this draft.** SQL provides structural constraints; CI and the future importer enforce canonical hashing, source fidelity, conflict decisions, complete classification coverage and publication operations. Foreign keys must be enabled on every connection; their deferral permits one atomic load transaction. The draft requires SQLite 3.38+ with JSON and STRICT support. [SQLite foreign keys](https://www.sqlite.org/foreignkeys.html), [STRICT tables](https://www.sqlite.org/stricttables.html), [JSON support](https://www.sqlite.org/json1.html).

Geometry/reform mapping, tightness/competition tables, full LatAm loading and regional-calendar materialization remain deferred. The current four European packages provide no populated regional-calendar proof; Andorra is preferred for Phase 2’s honest empty-state demonstration.
