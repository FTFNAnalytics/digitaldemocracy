# Belgium S2 identity rules

Accepted 2026-09-19 against review pack main `01602ea88de411fd712858e10e3f559d5ceb3ee1` (landing base `b293da99b97a8ae008d87ee2e57210cde0678004`). These are documentary vectors, not an executed importer. `Belgium_Identity_Vectors.json` enumerates every authored office, geography, event, result and source key. Input Inventory includes the candidate fingerprint and original bytes. Justin accepted all 1,234 draft offices; remaining-universe and historic successor notes stay open.

## Namespace and granularity

Country `belgium`, code `BE`; lineage/source namespace `country-package-belgium`; office/event namespace `cdd-observatory-v1`. Keep the reserved Belgium lineage across future S→S2 releases; S’s zero rows do not imply that Belgium has no elections. New research lives only at `data/research/belgium-s2/`. Nothing overwrites `data/countries/belgium/`.

Atlas office IDs here are newly **assigned documentary identifiers for sourced institutions**, not claims of pre-existing official Atlas IDs. Numeric codes preserve official NIS/election geography codes: `BE-<code>-C` council, `-M` mayor, `-PC` province council, `-DC` district council, `-SC` social-welfare council, `-EB` directly elected aldermen, `-SB` standing bureau. Named legislatures use `BE-FED-CH-P`, `BE-FED-SEN-P`, `BE-FL-P`, `BE-WA-P`, `BE-BR-P`, `BE-DE-P`, `BE-FR-COM-P`. Do not generate offices from dates, calendar labels, population totals, candidate counts or seat capacities. One council is one office, even with many seats. An indirect body is not a direct election.

## Exact deterministic functions

`C(x)` is compact UTF-8 JSON with recursively lexicographically sorted object keys, preserved array order, JSON scalar/null semantics and no trailing newline; no Unicode normalization of labels or URLs. `H(x)=SHA256(C(x))`, lowercase hex. `K(prefix,x)=prefix+'-'+H(x)[0:24]`, matching pinned `normalize.key`. All key inputs in vectors are strings/arrays, avoiding cross-language floating serialization differences.

Geography: numeric jurisdiction `BE-NIS-<code>`; named institutional geography `BE-GEO-<named code>`. Parents remain NULL unless separately sourced. NIS identity is not geometry: effective-boundary history remains raw/unresolved, particularly merger/recode predecessors. No geometry or retroactive boundary harmonization.

History key: `office_id+'::'+year+'::'+supplied_ISO_date`. Event ID: `K('event',['belgium',N,history_key])`. The exact namespace is carried in both PK and key input. One date/office event across overlapping sources; do not insert a second event from a comparison column, result row or reporting level. Conflict-case Bilzen keeps its original supplied-label HK for traceability, but resolves no typed date; a later accepted rebind preserves this alias in crosswalk rather than deleting it. Rounds/repeats require distinct evidenced event/proceeding identities, not arbitrary suffixes.

Result ID: `K('result',['belgium',N,HK,source_row_id])`. IBZ token=`ibz-<electionList.id>`; Flemish municipal/district/OCMW token=`fl-list-<list number>`; Flemish province token=`fl-district-<constituency code>-list-<list number>`; Wallonia token=`wa-list-<number>::<exact label>` (Liège reuses numbers for distinct language labels); Brussels token=`br-list-<printed list number>`. Never collapse party labels across districts or languages. Corrections to a label-dependent key require an explicit old→new crosswalk and retained claims, not silent rekeying. Source row numbers remain evidence locators, not identity inputs.

Source ID=`K('source',['belgium',exact_url])`; tool-capture files containing multiple official pages instead use their stable filename as the second key component and leave source.url NULL. Their embedded page URLs are evidence locators. A downloaded challenge page is retained as diagnostics, not counted as substantive evidence. Source table PK is `(belgium,L,source_id)`. No fake INE/API source catalogue IDs, publisher or legal certification. Upstream IBZ level/list IDs are preserved in raw and crosswalk, scoped by API election ID and entity kind.

Record key=`'rec-'+H([entity_kind,...PKcomponents])`. Office components `[N,office_id]`; event `[N,office_id,HK]`; result_row `[N,office_id,HK,result_row_id]`; country `['belgium']`; geography `['belgium',geography_id]`; source `['belgium',L,source_id]`; input `[L,input_path]`. Evidence ID=`'ev-'+H([record_key,input_path,locator,claim_kind])`; unresolved ID=`'unres-'+H([record_key,original_token,input_path,locator])`. Locators use exact RFC6901 pointers, 1-based XLSX sheet rows, or retained HTML XPath. Evidence hashes verify bytes but do not rekey a stable observation after a correction.

Date ID=`'date-'+H([N,owner_kind,owner_id,slot])`: event owner_kind=`election_event`, owner_id=event_id, slot=`ballot`; office next owner_kind=`office`, owner_id=office_id, slot=`next`. Historical day dates use precision day/certainty called, meaning date supplied by the election authority, not a certification claim. Flanders 2030 uses precision year/certainty expected, NULL month/day and no prospective event. Unknown next date creates no date row. Conflict dates have date_resolution conflicting and date_id NULL; preserve competing dated claims separately.

## Fingerprint and attempt/publication identity

Inventory `hash_inputs` is authoritative: all new research source/derived input paths, hashes and byte counts plus draft tier bytes; overrides=[]; adapter `atlas-belgium-full-register/1`; method `atlas-preserve-evidence/1`; schema `atlas-master/1`; canonicalization/hash versions and unchanged DDL hashes. Exclude handoff markdown, inventory self-hashes, ZIP bytes, main commit, times, operators, attempt IDs, absolute scratch paths and unrelated lineage inputs. `fingerprint=H(hash_inputs)`; `release_id=L+'--sha256-'+fingerprint`. Draft-tier candidate: `country-package-belgium--sha256-697589ef03168fe60be3ed6a8c761dc455ce20b59453142d03053c2294498073`. An accepted tier changes bytes and therefore creates a different release candidate. **No importer runs in this landing; the accepted-tier fingerprint is not published.**

Identical effective inputs produce the same R and a fresh attempt UUID. A sourced correction produces a new R while preserving public entity identities/crosswalks. An incomplete refresh never deletes omitted offices or historic results: retain old data and original inputs at `inherited/sha256/<hash>/<original path>` when paths collide; include inherited dependencies and classifications in effective fingerprint. Withdrawal needs an explicit reviewed claim. Historical status is not deletion.

Each office cites its own `(L,R)`, never the latest publication receipt. Belgium-only publication retains Albania/other Europe, LatAm and NZ selected releases and rows byte-for-byte logically. The durable attempt ledger survives discarded staging; no SQLite/VPS action runs here.

## Incomplete bindings and overlap

IBZ municipality aliases are only accepted when exact accent/punctuation-folded official labels resolve to one sourced code; all candidate codes and original labels are retained for 35 unresolved cases. That normalization is a binding aid, not an ID generator. Current NIS roster dominates current membership; 55 absent coded historical jurisdictions remain historical, with no invented effective end date. All unmatched raw records remain recoverable.

Flemish province district vectors share a province event but retain constituency scope per result; no duplicate province aggregate is authored and no province-wide margin is inferred. Candidate preference votes remain in original workbooks, separate from list ballots. Wallonia’s older comparison columns and subordinate rollups remain raw. Municipal results never become mayor votes. Senate/French Community appointment histories remain missing rather than borrowed from another body. The window never participates in office/history identity or retention.
