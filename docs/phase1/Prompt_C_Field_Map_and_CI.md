## Phase 1 required automated CI assertions

These are acceptance requirements for the future importer/CI PR. This DDL draft does not claim that implementation already exists. All tests use temporary paths, never the VPS production DB. FK checks must run with `PRAGMA foreign_keys=ON` verified as 1; fail the operation on any SQL error, not merely inspect the final statement’s exit code. Enable `recursive_triggers=ON`; prohibit `INSERT OR REPLACE`.

| Gate | Required assertion |
| --- | --- |
| Fresh migration | Both SQL files execute on their separate new DBs. Reject an unexpected existing schema. Master/ledger versions match expected migrations. Empty schema is not Phase 1 exit. |
| Actual Albania fidelity | Read accepted, checksummed inputs; compare all source IDs and semantic fields, not just counts. 122 offices, 366 selected histories, 3,843 result rows; all 122 classifications municipal; regional count exactly 0. This is a passing storage proof. Source-catalogue count 182 is distinct from any explicitly resolved inline additions. Preserve 122 briefing references and raw ancillary sheets. |
| Unchanged re-import | Run actual importer twice with identical canonical hash inputs. New attempt IDs; same release ID/fingerprint, identities, research dates and semantic content hashes; one immutable release row. Operational receipt/ledger fields may change, so do not demand identical DB-file bytes. Ignore wall-clock timestamps for the fingerprint. |
| Corrected import | Change a checksummed source or documented override in an isolated copy. Obtain a new lineage release, retain prior release metadata and recoverable full snapshot, preserve unchanged record IDs, and round-trip the changed claim. Tier/adapter/method/schema changes are hash inputs too. Same fingerprint with a different release ID must fail uniqueness. |
| Poison rollback | Begin a durable attempt, then inject a dangling event/source FK or corrupt input after some staged rows have been written. Run the actual publication path: nonzero exit, prior master file/release set/record values still served, failed attempt survives discarded staging, success-release pointer NULL, no newly published release. Test failures before validation and before rename. |
| Namespace and public IDs | Same office/history strings in separate test namespaces never cross-link. Wrong-namespace child FKs fail. Office/history/source/public event IDs round-trip; a legacy URL alias resolves to the same record. Existing result IDs are not reassigned to another candidate/list or event. |
| Broken references | Wrong/missing country, geography, office, event, proceeding, party mapping or resolved source fails closed. Require empty `foreign_key_check` and `integrity_check='ok'`. Typed locator/crosswalk targets exist. Nullable optional fields may be absent but must not hide a partially supplied composite reference. |
| Unresolved evidence | A legitimate unmatched token is retained as an unresolved record with original locator, without a fabricated source row, publisher or URL. Distinguish it from a known resolved source accidentally omitted by the importer. |
| Missing ≠ zero | 0 votes/share/seats round-trip as reported zero; missing remains NULL/unknown (or its supplied missing-status variant). Reject missing value with zero status and numeric value with unknown status. Preserve fractional shares without rounding; counts are integers. Do not turn missing elected flags into false. |
| Precision, certainty, conflicts | Day/month/year/range/unknown and called/statutory/expected/conditional/unknown round-trip. Month/year cannot acquire a fabricated day; invalid days fail. Compare ranges using interval overlap, including a year spanning a query window. Unknown is not confirmed in-window. Reject range cycles/unknown endpoints. Two unresolved date claims keep both sources and withhold the single date pointer. Do not treat Alderney’s two dates as one runoff range. |
| Tier source and empty state | Exactly one checksummed classification per office; file/register ID sets match. The stored tier equals the approved file row; changing cohort text cannot change it. Unknown tier stays NULL and flagged, not other. Known other/territory is representable. Approved regional numerator for all four current European packages is 0. No positive-regional-count launch/storage gate. |
| Fixture exclusion | Reject fixture provenance, FIX-/FXT- IDs, known fixture namespaces and fixture payloads across every entity and retained input. `OBSERVATORY_FIXTURES=1` cannot inject production rows. SQL prefix checks on offices/events are additional defenses, not the whole fixture test. |
| Score gates | Source score-gate false, withheld fields and incomplete series survive retained input exactly. This draft exposes no computed competition/tightness table. The future integration must not display them as cleared; retain this automated check even though derived metrics are deferred. |
| Incomplete refresh | Remove a row from a later incomplete test package: prior office/event/source survives with its original raw provenance. Only a documented withdrawal changes active state; stable record IDs remain addressable. Include retained source checksums in effective inputs. No silent identity reassignment. |
| Publication continuity | A small metadata/identity fixture can represent additional real lineage/country IDs without performing a full LatAm load. Europe-only import preserves the other selected lineage releases and rows; citations remain attached to their own lineage. Status-only countries need no dummy offices. No Europe-only enum or country-count ceiling. |
| Filesystem publication / recovery | Exercise writer contention; backup/read-only permissions; busy WAL checkpoint; safe connection closure; same-filesystem rename; fsync failure; crash before/after rename and before ledger success. Never serve a half-published DB. Reconcile the master attempt receipt on unchanged re-import too. Never delete live WAL/SHM blindly. |
| Restore | Restore a known prior snapshot into a scratch path; verify schema version, release set, office ID and content. Previous release audit must include row content via backup/rebuild, not just its metadata row. |
| Existing project gates | `npm test`, `npm run lint`, `npm run validate:data`, `npm run build` pass. No public route changes, redirects or tightness. After Phase 1 exits, stop for Phase 2 review. |

## What was checked for this draft

The migrations were executed against SQLite 3.53.1 in isolated temporary databases. The accompanying validation note records SQL constraint and transaction probes. These checks do **not** substitute for actual importer hashing, the full Albania field map/load, rendering or OS-level atomic publication CI.

SQLite references: [Foreign keys](https://www.sqlite.org/foreignkeys.html) explain per-connection enabling, composite NULL behavior and deferred constraints; [WAL](https://www.sqlite.org/wal.html) explains why a live WAL database cannot be treated as just its main file. The operational protocol remains the accepted Atlas plan.
